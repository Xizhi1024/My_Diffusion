## 三、CT-PET 对齐问题

### 3.1 分辨率不匹配

| 属性 | CT | PET | 差异 |
|------|-----|-----|------|
| 分辨率 | **512×512** | **192×192** | CT是PET的2.67× |
| 层厚 | **3.75 mm** | **3.27 mm** | PET层间距更密 |
| 像素类型 | signed 16-bit | signed 16-bit | 一致 |
| HU/Suv 编码 | Slope=1.0, Int=-1024, "HU" | Slope=0.440324, Units="BQML" | 需要不同的反量化 |
| 层数/患者 | 7.7 层 | 7.7 层（Image+Label一致） | CT和PET患者一一对应 |

**CT切片数与PET图像切片数不直接相等！** CT DICOM=1194，PET Image DICOM=1196，差2张。

### 3.2 文件名映射

| 类型 | DICOM命名 | PNG命名 |
|------|-----------|---------|
| CT Image | `{InstanceNumber}_{OtherNum}.dcm` | `{PatientID:3d}{SliceID:3d}.png` |
| CT Label | — | `{PatientID:3d}{SliceID:3d}.png` |
| PET Image | `{InstanceNumber}_{OtherNum}.dcm` | `{PatientID:3d}{SliceID:3d}.png` |
| PET Label | `IMG{Num}.dcm` | `{PatientID:3d}{SliceID:3d}.png` |

**DICOM 和 PNG 使用完全不同的命名规范**。PNG 格式已被预处理为 `PatientID+SliceID` 格式，与 DICOM 原始 InstanceNumber 无直接对应关系。需要通过 DICOM 的 InstanceNumber 和 SliceLocation 进行重新排序和匹配。

### 3.3 PNG Label 分析

```
格式:    uint8, 192×192（已resize到PET尺寸）
取值:    仅 {0, 255}（二值mask）
非零比:  0.1% ~ 0.24%（病灶极小！）
```

**病灶占比约 0.1-0.2%**：192×192=36,864 像素中仅约 37-90 个病灶像素。这就是文档中反复强调"小目标"的直接证据。

## 四、数据量评估：这对架构意味着什么

### 4.1 核心事实

| 事实 | 对架构的影响 |
|------|-------------|
| **1,194 张切片（非3D体积）** | 不能做真3D卷积。按切片训练是唯一选择 |
| **平均 7.7 层/患者** | 2.5D (5-slice) 勉强可行，但对≤4层的37名患者(24%)无效 |
| **仅 152 训练患者** | 参数多的模块（GNN, Mamba, Cross-Attn）容易过拟合 |
| **病灶占比 0.1-0.2%** | 极度类别不平衡。Focal/Top-K Loss 不是可选而是必需 |
| **CT 512² vs PET 192²** | 需要空间配准+resize，高频纹理在resize中会丢失 |
| **仅 3 测试患者(26张切片)** | **测试集无法支撑统计显著性检验**（文档11.6要求≥35例中效应） |

### 4.2 架构降级建议

| 原架构模块 | 数据是否支撑 | 建议 |
|-----------|-------------|------|
| 2.5D 5-slice 堆叠 | ⚠️ 对24%患者不可用 | 自适应：≥5层→5-slice, 3-4层→3-slice, 1-2层→单层+padding |
| GNN 盆腔拓扑图（2.4） | ❌ 152例远不够 | **降级为固定器官分割mask concat** |
| Mamba Bottleneck（5.2） | ⚠️ 边界 | 替换为轻量深度可分离卷积或保留但大幅减少dim |
| Cross-Attn Token注入（4.2） | ⚠️ 需极简dim | 1-2个token，32-64维，不能再大 |
| 冻结DINOv2特征（2.3） | ✅ 可行 | 冻结不训练，反而不吃数据 |
| ControlNet 多尺度注入（4.1） | ✅ 可行 | 参数独立但复用UNet结构 |
| 频域Gabor分支（2.1） | ✅ 可行 | 滤波器可学习参数量很小（32个频率+方向+尺度） |
| 尺度感知噪声调度（6.4） | ✅ 可行 | 本质是超参数设计，不增加参数量 |
| Top-K Focal Loss（7.3.1） | ✅ 必要 | 病灶0.1%占比下这是生存必需品 |
| PatchNCE（7.2.3） | ⚠️ 切片级可行 | 不要做3D patch，做2D patch；温度参数需仔细调节 |
| 异方差NLL（7.5.1） | ✅ 可行 | 输出增加1个logvar通道，参数增量极小 |
| 分割闭环（7.4） | ⚠️ 需联合训练 | 如果分割器本身在小数据上不稳，梯度反传可能有害 |
| Latent Diffusion（5.5） | ❌ 1,194张切片不够训VAE | 保持像素空间扩散；如要latent，用预训练VAE |
| DiT / 纯Transformer（5.4） | ❌ 完全不够 | 放弃。CNN-based U-Net + 轻量bottleneck是上限 |

### 4.3 测试集问题：3个患者(26张切片)不够

文档11.6要求的样本量：
- 大效应(d≈0.8)→15-20例
- 中效应(d≈0.5)→35-45例（论文主实验最低要求）

**当前仅3个测试患者**，无法满足论文的统计检验规范。**必须增加测试集或引入外部验证数据**（ECPC-IDS公开数据集是自然的补充）。

## 五、数据预处理 Pipeline 现状

```
DICOM (512×512 CT / 192×192 PET)
    │
    ▼
Python 预处理脚本（用户已实现）
    │  - CT: HU恢复 (RescaleSlope/Intercept)
    │  - PET: SUV转换 (RescaleSlope→BQML)
    │  - Resize到统一尺寸
    │  - 0-255 uint8 PNG输出
    │
    ▼
PNG (192×192)
    │  - ImageSet: CT图像 / PET图像（uint8, 单通道灰度）
    │  - LabelSet: 二值分割mask（uint8, {0,255}）
    │
    ▼
命名: {PatientID:3d}{SliceID:3d}.png
    │  - 例: "004001.png" = 患者004, 第1张切片
    │  - 同一文件名在 CT ImageSet / PET ImageSet / CT LabelSet / PET LabelSet 下表示对应关系
```

### PNG 格式已确认的退化

| CT DICOM 原始 | PNG 转换后 |
|--------------|-----------|
| 16-bit signed, HU physical values | **8-bit uint8, HU信息丢失** |
| RescaleIntercept=-1024, Slope=1.0 | 线性映射→0-255 |

文档1.2 的"CT HU值严格恢复"和 1.3 的"PET数值语义统一"**在PNG管线中并未实现**。如果模型输入是PNG，那HU/SUV的物理意义确实被丢失了——这与架构文档的设计意图矛盾。

## 六、总结：数据支撑的现实架构上限

```
实际情况: 1,194张2D切片 × 152患者 × 二值label(0.1%非零)

可以做到的:
  ✅ 2D U-Net 扩散backbone (512² CT → resized 192² PET)
  ✅ ControlNet 多尺度CT条件注入
  ✅ 频域Gabor可学习滤波器分支（参数量极小）
  ✅ 冻结DINOv2/RadImageNet特征作为额外语义token (1-4 tokens)
  ✅ 异方差不确定性输出 (+1 channel)
  ✅ 布朗桥扩散过程 (BBDM)
  ✅ Top-K Focal Loss + Focal Frequency Loss + PatchNCE
  ✅ DDIM 20步采样

需要降级的:
  ⚠️ 2.5D→自适应层数（单层为主，多层可选）
  ⚠️ GNN→固定器官mask concat
  ⚠️ Mamba→轻量深度可分离卷积bottleneck
  ⚠️ Cross-Attn→极简（1-2 token, 32-64 dim）

需要放弃的:
  ❌ 3D卷积
  ❌ Latent Diffusion (训自己的VAE)
  ❌ DiT / 纯Transformer backbone
  ❌ 大参数量GNN

必须解决的外部问题:
  🔴 测试集仅3患者(26切片) → 引入ECPC-IDS或外部数据
  🔴 PNG丢失HU/SUV物理语义 → 改用DICOM→NIfTI管线或保留16-bit
```
